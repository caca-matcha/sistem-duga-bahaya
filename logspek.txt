# 🧬 **2. ERD (Entity Relationship Diagram)**

Berikut skema ERD versi tulisan (bisa digambar ke draw.io atau mermaid):

```
TABLE users
------------
id (PK)
name
email
password
role (admin/karyawan)
created_at
updated_at


TABLE maps (denah pabrik / area / line)
------------
id (PK)
name
type (pabrik/area/line)
parent_id (FK to maps.id)
background_image (nullable)
rows
cols
created_by (FK to users.id)
created_at
updated_at


TABLE cells (setiap grid)
------------
id (PK)
map_id (FK to maps.id)
row_index
col_index
area_id
area_name
area_type
risk_score
zone_color
metadata (json)
created_at
updated_at


TABLE risk_parameters
---------------------
id (PK)
cell_id (FK to cells.id)
parameter_name
value
created_at
updated_at
```

### **Relasi**

* **1 maps → banyak cells**
* **1 cell → banyak parameter risiko**
* **1 maps → banyak maps (jika pabrik → area → line)** lewat parent_id
* **1 user (admin) → banyak maps dibuat**

Tinggal bilang, nanti aku buatkan versi visual + versi PDF siap untuk dipakai presentasi ke perusahaan atau sebagai dokumentasi developer.


Secara sederhana, Master Data yang kamu buat di sisi Admin (SHE) bertindak sebagai "Pusat Kebenaran". Jadi, semua menu lainnya (Peta Risiko dan Form Karyawan) hanya tinggal "menumpang" atau mengambil data dari situ.
1. Langkah Pertama: Isi Master Data (Admin SHE)
Di menu baru yang kita bahas tadi (Administrasi > Master Lokasi), kamu mendaftarkan semua titik lokasi secara lengkap.

Contoh Input: Nama: "Temporary Storage Rack", ID: "GA-TSR-01", Type: "Storage", Gedung: "Gedung A".

Hasil: Data ini tersimpan permanen di database.

2. Langkah Kedua: Hubungkan ke Peta Risiko (Grid Editor)
Saat kamu membuka Grid Editor di menu Peta Risiko:

Kamu tidak lagi mengetik manual nama lokasi di setiap kotak grid.

Kamu cukup klik cell/kotak di grid, lalu akan muncul dropdown yang isinya mengambil data dari Master Data tadi.

Keuntungan: Satu lokasi di Master Data bisa kamu "tempel" ke banyak kotak grid tanpa harus mengetik ulang, sehingga tidak akan ada typo.

3. Langkah Ketiga: Otomatisasi di Form Karyawan
Inilah bagian yang menyelesaikan masalah di gambar yang kamu kirimkan:

Dropdown Lokasi: Di form karyawan, dropdown "Lokasi Kejadian" tidak lagi mengambil data dari "ketikan manual" atau "setiap kotak grid", melainkan mengambil data unik dari Master Data.

Hasil: Nama "Temporary Storage Rack" hanya akan muncul satu kali di dropdown, meskipun di peta aslinya lokasi tersebut mencakup 5 kotak grid.

Auto-fill: Begitu karyawan pilih lokasi tersebut, sistem langsung tahu bahwa itu adalah GA-TSR-01 dan tipenya Storage karena datanya sudah terhubung di belakang layar.





✦ Klarifikasi baru ini sangat membantu. Tujuan akhirnya adalah, dari "peta risiko pabrik" di tampilan karyawan, ketika sebuah area (sel)      
  diklik, ia akan membuka halaman "peta risiko gedung" yang sesuai.

  Ini menyiratkan bahwa satu sel di "peta risiko pabrik" merepresentasikan satu peta "gedung" yang diagregasi. Data gedung_map_id yang        
  disimpan dalam metadata sel "pabrik" harus tunggal.

  Berikut adalah revisi rencana berdasarkan pemahaman ini:

  Fase 1: Backend - Model Data & Agregasi (Fokus pada Satu Gedung per Sel Pabrik)
   * Tugas 1 & 2 (Selesai): Verifikasi tipe peta dan metode getGedung.
   * Tugas 3 (Revisi): Mengimplementasikan logika backend baru di CellController@store dan CellController@update untuk sel "pabrik":
       * Validasi untuk gedung_map_id (tunggal) untuk sel "pabrik".
       * Logika Agregasi: Ketika sel "pabrik" disimpan, ia akan mengambil satu gedung_map_id. risk_score -nya akan menjadi rata-rata skor     
         risiko dari sel-sel di dalam satu gedung_map_id yang ditentukan tersebut.
       * Menyimpan satu gedung_map_id ini di kolom metadata sel "pabrik".
       * Menghitung risk_score dan zone_color.

  Fase 2: Frontend - Implementasi UI/UX untuk Grid Editor (Tampilan SHE)
   * Tugas 4: Memodifikasi grid-editor.jsx untuk membedakan perilaku peta "pabrik" dari peta "gedung".
   * Tugas 5: Di grid-editor.jsx, mengimplementasikan tampilan jumlah sel yang dipilih.
   * Tugas 6: Di grid-editor.jsx, mengimplementasikan dropdown untuk memilih satu peta "gedung" yang sudah ada saat mengedit sel "pabrik",

   * Tugas 7: Di grid-editor.jsx, memodifikasi logika penyimpanan sel untuk menyertakan gedung_map_id yang dipilih dan mengirimkannya ke
